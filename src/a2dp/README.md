# A2DP Sink (тестовый подпроект)

Bluetooth-приёмник аудио для ESP32 (Wrover-Kit): телефон подключается по
A2DP и играет музыку через внешний DAC на I2S.

## Что делает

ESP32 выступает BT-колонкой (`yoRadio_Wrover_Sink`). Принятый PCM-поток
библиотека ESP32-A2DP сама пишет в I2S, дальше — на внешний DAC.

## Подключение DAC (Wrover-Kit)

| Сигнал | Пин ESP32 |
|--------|-----------|
| BCK    | GPIO26    |
| WS     | GPIO25    |
| DIN    | GPIO27    |
| GND    | GND платы |

GPIO22 на Wrover-Kit не использовать — занят периферийными разъёмами.

## Сборка и прошивка

Окружение: `a2dp_sink` (собирает только `src/a2dp/main.cpp`).

```bash
pio run -e a2dp_sink -t upload
pio run -e a2dp_sink -t monitor



Платформа — та же espressif32@~8.0.0, что и у основного проекта (ядро 3.3.12). Никаких пинов ядра и pio pkg install не требуется: общая папка пакетов не свопается, т.к. все env проекта стоят на одной платформе.

Проверка работоспособности
Подключить телефон к yoRadio_Wrover_Sink, запустить музыку — звук в колонках.
Для контроля потока (опционально) добавить колбэк через set_on_data_received(): норма ~176 400 Б/с при 44.1 кГц / 2 кан. / 16 бит.
Важно знать
Не использовать set_stream_reader(cb, false) — второй аргумент false отключает вывод на I2S: поток принимается и выбрасывается, счётчик при этом показывает честные ~176 400 Б/с, а звука нет. Диагноз, на который ушла неделя.
Синус-тест железа: генератор 440 Гц прямо в I2S без Bluetooth — см. историю коммитов (версией выше текущего main.cpp).


## Дальше — доводим синк

Мой план «до коммерческого состояния», по возрастанию полезности:

1. **Метаданные по AVRCP** — название трека, исполнитель, статус play/pause в монитор (потом легко вывести на дисплей yoRadio);
2. **Автоподключение** — телефон снова в зоне видимости → синк подхватывает сам;
3. **Громкость** — управление AVRCP-громкостью из колбэка, задел под энкодер;
4. **Чистое отключение** — пауза при разрыве связи, чтобы не было артефактов.

Начинать предлагаю с пункта 1 — метаданные сразу дают видимый результат и ставят мост к будущей интеграции с дисплеем. Делаем?
